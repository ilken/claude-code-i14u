## 2026-07-23 boulevard-dex - Chrome-extension viewport checks: resize_window can silently no-op

- `mcp__claude-in-chrome__resize_window` reported success but `window.innerWidth` stayed at desktop size (macOS Chrome min-width / window manager). Always verify with `window.innerWidth` via `javascript_tool` after resizing.
- Workaround for responsive spot-checks of a specific component: temporarily set the component's container width via JS (e.g. `container.style.width = '343px'`), measure `getBoundingClientRect()` for wrap/overflow, then revert. Doesn't exercise media queries, but validates flex-wrap/overflow behavior of the element under test.
- Also: right after a `navigate`, coordinate clicks can silently miss; verify state changes via `javascript_tool` (read localStorage/aria attributes) instead of trusting the click, and prefer `find` → ref clicks or a fresh screenshot for coordinates.

## 2026-07-10 minechester-reborn - Unstable hook wrapper objects starve timeouts/intervals

- A hook that returns a fresh object literal each render (e.g. `useGameTimer` returning `{ elapsedMs, start, stop, reset }`) defeats memoization for every downstream `useCallback`/`useEffect` that lists that object in its deps — even if the callbacks inside are `useCallback([])`-stable. The effect re-runs on every render.
- Failure mode: an effect that arms a `setTimeout`/`setInterval` and clears it in cleanup gets torn down and re-armed on each render. If another state (a running clock via `setInterval(…, 33)`) forces frequent re-renders, the timer's delay (550ms AI move / 320ms solver) never elapses — it looks "stuck" (Challenge AI froze on "thinking…"; solver never advanced).
- Fix: destructure the stable callbacks and depend on those individually (`start`/`stop`/`reset`), not the churning wrapper. Don't put a value that changes every tick (`elapsedMs`) on the critical effect's dependency path.

## 2026-07-09 ilken.github.io - React event handler style

- User preference (applies to all React projects): no inline arrow-function click handlers in JSX. Define handlers with `useCallback` at the top of the component; for handlers over mapped items, use a curried `useCallback((item) => () => ...)` factory.

## 2026-07-09 GameOfColours - Browser-verifying rAF-driven canvas games

- The Claude-in-Chrome automated tab runs with `document.visibilityState === 'hidden'` even while interactive, so browsers throttle/pause `requestAnimationFrame`. Any PixiJS ticker / rAF loop (countdown timers, tween animations) freezes between actions — a stuck timer bar is a test-harness artifact, not a bug. Verify rAF-independent paths (click handlers, state) live, and confirm the rAF paths by code review. Check `document.visibilityState` before concluding a timer is broken.
- The 1Password extension autofills any 3-char/text `<input>` and its iframe steals focus, after which every `computer` click/type and even `javascript_tool` fails with "Cannot access a chrome-extension:// URL of different extension". Recover by `navigate`-reloading the page (a browser-level action that isn't blocked), then drive inputs via `javascript_tool` using the React-compatible native setter + `input` event instead of typing.
- TanStack Router file-based routing: `src/routeTree.gen.ts` is generated by the vite plugin on dev-server start and must exist before `tsc -b` (the `build` script runs typecheck first). On a fresh scaffold, run `yarn dev` once to generate it, then commit it (it's git-tracked but eslint/prettier-ignored).

## 2026-07-09 minechester-reborn - GitHub name collisions and dev-server pipes

- GitHub repo names are case-insensitive: `gh repo create ilken/minechester` failed with "name already exists" because the 2014 `ilken/Minechester` occupies the slug — and a plain `git push` to the lowercase URL lands in the original repo. Check `gh repo view <owner>/<name>` before creating when an old similarly-named repo might exist
- Never start a dev server with `... | head -N` in a background task: head closes the pipe and vite dies on SIGPIPE the next time it writes (server silently gone mid-verification). Run it bare and Read the output file instead
- For a fresh repo with a PR-based flow, push the root commit as `main` (`git push origin $(git rev-list --max-parents=0 HEAD):refs/heads/main`) so the feature branch has a base to PR against without committing to main

## 2026-07-08 boulevard-dex - Fandom wiki scraping: use the MediaWiki API, expect WebP

- Fandom wiki HTML pages 403/402 curl and WebFetch, but the MediaWiki API (`<wiki>.fandom.com/api.php?action=parse&page=<title>&prop=text`) returns the full parsed page HTML to curl/fetch with a plain browser UA — tables, image URLs and all
- `static.wikia.nocookie.net` image URLs download fine, and `/scale-to-width-down/<w>` mid-path resizes server-side; but the CDN transcodes everything to WebP regardless of extension or Accept header — store as `.webp`, don't fight it
- Hot Wheels wiki year pages ("<year> Hot Wheels Boulevard") have per-car tables with a "Series #" column and "Photo Loose"/"Photo Carded" figures — series# → image mapping made a 150/150 photo harvest trivial

## 2026-07-08 f1-calendar - F1 race data sourcing and tzdata hydration mismatches

- Jolpica API (`api.jolpi.ca/ergast/f1/<year>/races/`) is the cleanest F1 calendar source: exact UTC race times, sprint flags, circuit/locality — and it reflects reality (2026 is 22 rounds; Bahrain/Saudi were cancelled), unlike stale announcement articles
- F1 media CDN hosts official track maps at `media.formula1.com/image/upload/c_fit,h_704/f_png/common/f1/<year>/track/<year>track<slug>detailed.png` (white-line-on-transparent art); scrape the race page HTML for exact asset URLs, and verify f1.com race-page slugs with curl — they change between seasons (2026: `barcelona-catalunya`, `united-arab-emirates`)
- Next.js hydration: UTC-offset labels from `Intl`/date-fns-tz can differ between Node and Chrome because their tzdata versions disagree (e.g. America/Asuncion post-DST-abolition) — generate such labels in `useEffect`, never at module scope

## 2026-07-07 ilken.github.io - react-hooks/set-state-in-effect forbids measure-then-set effects

- The new `react-hooks/set-state-in-effect` ESLint rule (React Compiler era) errors on any synchronous `setState` in an effect body — the classic "measure DOM in useLayoutEffect, set state" pattern fails lint
- Sanctioned alternative: create a `ResizeObserver` in the effect and call `setState` inside the observer callback (external-system subscription); it also fires once on `observe()`, so no separate initial measure is needed and you get resize handling for free

## 2026-07-07 ilken.github.io - Chrome background-tab throttling breaks screenshot-based UI testing

- In an unfocused Chrome window/tab (as with the Claude extension driving a background tab), CSS entrance animations and image compositing are throttled: pages driven by `.stagger` fade-ups screenshot as blank/faded even though the DOM is complete
- Don't chase it as a product bug: verify with `get_page_text` / `read_page` / JS (`img.complete`, `naturalWidth`) — if content exists in the DOM, it's the throttle; re-screenshot after extra waits and it eventually composites
- Open Library covers: `https://covers.openlibrary.org/b/isbn/{isbn}-L.jpg?default=false` returns 404 for missing covers (deterministic `onError` fallback); verify ISBNs with curl before shipping

## 2026-06-13 ilken.github.io - Apple iTunes API CDN CORS cache poisoning
- Apple's CDN caches the `Access-Control-Allow-Origin` response header per URL without `Vary: Origin`
- If a fetch is first made from a dev origin (e.g. `localhost:4173`), Apple's CDN serves `ACAO: localhost:4173` to ALL subsequent requests to that URL, including from production
- Fix: append a versioned param to the URL (e.g. `?v=1`) so the CDN treats it as a new entry with the correct production origin reflected back
- When testing CORS from curl, always pass `-H "Origin: https://your-production-domain"` to get the actual header the browser will see

## 2026-06-13 ilken.github.io - GitHub Pages + TanStack Router SPA 404 fallback
- Copy `dist/index.html` to `dist/404.html` in the build script; GitHub Pages serves `404.html` for unknown routes so the SPA can take over client-side
- Deep links return HTTP 404 status (expected) but serve the app HTML — valid behaviour for this pattern
- GitHub user pages deploy from the default branch; set `branches: [master]` in the workflow trigger to match whatever your actual default branch is

## 2026-06-12 claude-code-i14u - Claude Code hooks: stdin JSON, exit 2 to block
- Hooks receive tool input as JSON on **stdin** (`jq -r '.tool_input.command'`), not via env vars — `$CLAUDE_TOOL_INPUT` does not exist and silently expands to empty
- Only **exit 2** blocks an action in PreToolUse hooks; exit 1 is a non-blocking error and the action proceeds
- Always test hooks by piping sample JSON (`echo '{"tool_input":{...}}' | bash -c "$HOOK"`) — broken hooks fail silently and give false confidence
- `CLAUDE_PROJECT_DIR` is available to hooks; use `git -C "$CLAUDE_PROJECT_DIR"` so the hook works regardless of cwd

## 2026-04-14 affiliate-link-sniper - App-specific env files, no web Dockerfile
- `.env.example` lives in each app (`apps/backend/.env.example`, `apps/web/.env.example`), never at the repo root
- The web app has no Dockerfile — it runs with `yarn dev` locally, not in Docker
- Docker Compose uses `env_file: ./apps/backend/.env` on all services that need it (postgres + backend); `environment:` block overrides container-specific hostnames (e.g. `DATABASE_URL` pointing to `postgres` instead of `localhost`)
- No root `.env` or `.env.example` needed; docker-compose variable substitution is avoided by using `env_file` directly

## 2026-03-18 Backend - MUTUAL friendship status is symmetric
When querying `findManyFriends` with `status: [FriendshipStatus.MUTUAL]`, only one direction needs to be checked. If A→B is MUTUAL, B→A is inherently mutual too. Don't query both `(requesterProfileId: [author], recipientProfileId: targets)` and the reverse — one query is sufficient.

## 2026-03-18 Backend - Wrap non-critical side effects in try-catch
Secondary operations like mention creation should be wrapped in try-catch so failures don't break the primary flow (post/reply creation). Log the error and return silently. This applies to any write-path side effect that isn't essential to the main operation's success.

## 2026-03-13 Backend - Fail closed in authorization/evaluation logic
When writing code that evaluates conditions for access control (e.g., channel join conditions, permission checks), always handle the default/unexpected case by denying access (`satisfied = false`). Use explicit `switch` with `default: satisfied = false` rather than `if/else` chains that silently skip unknown values. Failing open in auth logic means malformed data can grant unintended access.
---

## 2026-03-13 Backend - Submodule folder structure must mirror parent conventions
When creating a submodule (e.g., `chat-channel-conditions/` under `chat-channel/`), follow the same folder structure as the parent module: entities go in `entities/`, models go in `models/`, DTOs in the root or a `dto/` folder. Never put entity or model files directly in the submodule root. The architecture skill documents this pattern — always check `skills/backend/architecture.md` before creating new modules.
---

## 2026-03-13 Backend - Service access patterns: use public API modules
Don't import internal sub-modules (e.g., `ProfileFollowModule`, `CollectedModule`) into other domain modules. Access their services through the parent module's public service (e.g., `ProfileService.isFollowingMany()`, `CollectableService.findAllCollectedCollectableItemIds()`). If a passthrough method doesn't exist, add one to the parent service.
---

## 2026-03-13 Backend - DTOs for service return types, types for args
Service methods should return class-based DTOs (in `.dto.ts` files), not plain type aliases. Constructor args stay in `.types.ts` files. DTOs use a props-object constructor pattern with `public readonly` fields. See `chatroom-join-condition-evaluation.dto.ts` as reference.

## 2026-03-13 Backend - Rebase strategy for stacked PRs
When a feature branch contains commits from a previously merged PR, don't rebase (causes conflicts). Instead: create a temp branch from `origin/main`, cherry-pick only the new commits, force-push to the PR branch, then delete the temp branch.

## 2026-03-13 Backend - Always run yarn code:full-lint before committing
`yarn code:tsc` only checks types. `yarn code:full-lint` runs prettier + eslint + tsc. Import ordering issues and formatting are only caught by the full lint. Always use full lint as the final validation step.
---

## 2026-03-13 Backend - Test with different requesting users
When testing per-user evaluation (e.g., conditions, permissions), always include at least one test where the requester is NOT the channel owner/creator. Otherwise a bug that evaluates against the owner instead of the authenticated caller would pass the entire suite.
---

## 2026-03-13 Backend - Normalise invalid data at the mapping boundary
When mapping ordered array inputs (e.g., condition groups), enforce invariants at the mapper — e.g., the first element's `combinator` must be null because it has nothing to combine with. Don't trust client input for positional semantics.

## 2026-03-12 Backend - ObjectType constructors must use named props type
GraphQL ObjectType constructors should accept a single named props type (defined locally or in `.types.ts`) instead of positional parameters. This follows the repo convention against inline types and makes field additions safer.
